# Ticket: แอป PaynEat POS บน Google Play — ใส่ที่อยู่เซิร์ฟเวอร์ได้เอง และลองโหมดสาธิตได้โดยไม่มีเซิร์ฟเวอร์

**Priority:** 🟠 High — ช่องทางแรกที่ร้านติดตั้งเองได้จาก store (`docs/DECISIONS.md` #69)
**Ref:** `docs/DECISIONS.md` #67 (POS ฟรีทั้งหมด), #69 (การแจกจ่าย POS)
**Blocked by:** ไม่มีในโค้ด — แต่การขึ้น production ต้องรอเจ้าของเปิดบัญชี Google Play Console (ดู "สิ่งที่เจ้าของต้องทำ")

## ปัญหา
แอปมือถือ/แท็บเล็ตของ POS รู้ที่อยู่เซิร์ฟเวอร์ได้**ตอน build เท่านั้น** (`--dart-define=API_BASE_URL` ใน
`app/lib/app/config/app_config.dart`) และโหมดสาธิตก็เปิดได้ตอน build เท่านั้น (`DEMO_MODE`) แอปตัวเดียวที่ขึ้น store
จึงใช้กับร้านไหนไม่ได้เลย: ทุกร้านมีเซิร์ฟเวอร์ของตัวเองคนละที่อยู่ และคนที่โหลดมาลองหรือผู้ตรวจของ Google ก็ไม่มีเซิร์ฟเวอร์

## ทำไมสำคัญ
เจ้าของต้องการให้ร้านติดตั้งเองได้บนมือถือ แท็บเล็ต และ PC โดยไม่ต้องมีนักพัฒนา ร้านไทยส่วนใหญ่ใช้แท็บเล็ต Android ราคาไม่แพง
Google Play จึงเป็นช่องทางที่คุ้มที่สุดช่องทางแรก (ค่าสมัครครั้งเดียว) และเป็นหลักฐานว่า "open source ฟรี" ติดตั้งได้จริงเหมือนแอป
เสียเงิน

## ขอบเขตงาน
- **ตั้งที่อยู่เซิร์ฟเวอร์ตอนใช้งาน**: เปิดแอปครั้งแรก (ไม่ได้ build ด้วย `API_BASE_URL`) เจอหน้า "เชื่อมต่อเซิร์ฟเวอร์ร้าน"
  - พิมพ์ที่อยู่ หรือ**สแกน QR** ที่หน้าตั้งค่าของ admin บนเครื่องที่ต่อแล้วแสดงไว้ (เพิ่ม QR นั้นในหน้าตั้งค่า)
  - ตรวจด้วย `GET /health` ก่อนบันทึก บอกเหตุผลเป็นภาษาคนเมื่อไม่ผ่าน (ต่อไม่ได้ / ไม่ใช่เซิร์ฟเวอร์ PaynEat / เวอร์ชันไม่เข้ากัน)
  - เปลี่ยนที่อยู่ได้ภายหลังจากหน้าตั้งค่า (admin เท่านั้นเมื่อ login แล้ว หรือจากหน้า login เมื่อยังต่อไม่ได้)
  - build ที่ส่ง `API_BASE_URL` มายังทำงานเหมือนเดิมทุกประการ (web ที่ nginx เสิร์ฟ, e2e)
- **โหมดสาธิตตอนใช้งาน**: หน้าเชื่อมต่อมีปุ่ม "ลองใช้โดยไม่มีเซิร์ฟเวอร์" เข้าโหมดสาธิตเดิม (ข้อมูลจำลองในเครื่อง) พร้อมแถบบอก
  ตลอดว่าเป็นโหมดสาธิต และออกกลับมาหน้าเชื่อมต่อได้ — ผู้ตรวจของ store ต้องใช้ทางนี้
- **HTTP ในร้าน**: เซิร์ฟเวอร์ในร้านมักเป็น `http://192.168.x.x` ซึ่ง Android 9+ บล็อกโดยค่าเริ่มต้น
  - ยอมให้ต่อ HTTP ได้ แต่แสดงคำเตือนถาวรในหน้าตั้งค่าว่าการเชื่อมต่อไม่เข้ารหัส และแนะนำ HTTPS ถ้าเซิร์ฟเวอร์อยู่นอกร้าน
  - ห้ามส่งรหัสผ่านไปยังที่อยู่ที่เป็น IP สาธารณะผ่าน HTTP (ปฏิเสธพร้อมเหตุผล)
- **release build ที่ลงนามได้ใน CI**: job แยกที่ build `.aab` เมื่อมี tag โดยใช้ upload key จาก GitHub Secrets
  (ไม่อยู่ใน repo เด็ดขาด) ใช้ Play App Signing, `versionCode` มาจาก tag, และแนบ `.aab` กับ GitHub Release
- **หน้านโยบายความเป็นส่วนตัว** (ไทย/อังกฤษ) บน landing page: แอปไม่ส่งข้อมูลใดๆ มาหาผู้พัฒนา ข้อมูลร้านอยู่บนเซิร์ฟเวอร์ของร้าน
  เท่านั้น — พร้อมคำตอบแบบฟอร์ม Data safety ของ Play เขียนไว้ใน `docs/` ให้เจ้าของคัดลอกไปกรอก
- **หน้า store** (ไทย/อังกฤษ): ข้อความและภาพหน้าจอจากตัวสร้างภาพหน้าจอที่มีอยู่ ไม่ถ่ายใหม่ด้วยมือ
- **README**: หัวข้อติดตั้งมีทาง "โหลดจาก Google Play" คู่กับ Docker และบอกตรงๆ ว่าแอปต้องมีเซิร์ฟเวอร์ร้าน
  (หรือใช้โหมดสาธิต)

## ขอบเขตที่ตั้งใจไม่ทำ
- App Store (iOS) — ทำหลัง Play ตาม #69
- แอป desktop — PC ใช้เบราว์เซอร์ได้อยู่แล้ว
- ค้นหาเซิร์ฟเวอร์ในวง LAN อัตโนมัติ (mDNS) — QR พอสำหรับรอบแรก
- เซิร์ฟเวอร์บนมือถือ — เซิร์ฟเวอร์ยังอยู่บน PC/กล่องในร้านเหมือนเดิม

## สิ่งที่เจ้าของต้องทำ (โค้ดทำแทนไม่ได้)
- เปิดบัญชี Google Play Console (ค่าสมัครครั้งเดียว) — **บัญชีบุคคลที่เปิดใหม่ต้องผ่านการทดสอบแบบปิดกับผู้ทดสอบจำนวนหนึ่ง
  เป็นระยะเวลาหนึ่งก่อนขึ้น production** ส่วนบัญชีองค์กรต้องมี D-U-N-S ให้ตรวจเงื่อนไขล่าสุดใน Play Console ก่อนตัดสินใจ
- สร้าง upload key แล้วใส่ใน GitHub Secrets
- ตรวจเรื่องเครื่องหมายการค้าชื่อ PaynEat (ERP ADR-0015 ข้อ 10) ก่อนเปิดหน้า store สาธารณะ

## Acceptance Criteria
- [ ] แอปที่ไม่ได้ build ด้วย `API_BASE_URL` เปิดมาที่หน้าเชื่อมต่อ ใส่ที่อยู่หรือสแกน QR แล้วใช้งานกับเซิร์ฟเวอร์ร้านได้
- [ ] ที่อยู่ผิดแต่ละแบบได้เหตุผลที่อ่านเข้าใจ ไม่ใช่ error ของ Dio
- [ ] "ลองใช้โดยไม่มีเซิร์ฟเวอร์" เข้าโหมดสาธิตได้และออกได้ ไม่มีคำขอใดวิ่งออกเครือข่ายในโหมดนี้
- [ ] HTTP ในร้านใช้ได้พร้อมคำเตือน และไม่ส่งรหัสผ่านไป IP สาธารณะผ่าน HTTP
- [ ] build ที่มี `API_BASE_URL` (web/e2e) ทำงานเหมือนเดิม เทสต์เดิมผ่านโดยไม่แก้
- [ ] CI สร้าง `.aab` ที่ลงนามแล้วจาก tag โดยไม่มี key ใน repo
- [ ] หน้านโยบายความเป็นส่วนตัวและคำตอบ Data safety พร้อม
- [ ] README (ไทย/อังกฤษ), `docs/DECISIONS.md`, `docs/FEATURE-GAP-ANALYSIS.md` อัปเดตตาม `CLAUDE.md`
