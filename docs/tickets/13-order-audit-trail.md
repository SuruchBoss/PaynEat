# Ticket: Audit ระดับ "ใครกดสั่ง/แก้ไขออเดอร์" (Order Audit Trail)

**Priority:** ผู้ใช้ร้องขอโดยตรง (ไม่ได้มาจาก gap analysis เดิม)
**สถานะ:** ✅ เสร็จแล้ว
**Ref:** ต่อยอดจาก `docs/tickets/08-audit-log.md`, `docs/DECISIONS.md` #21 และ #25

## ปัญหา

Audit log เดิม (ticket 08) บันทึกเฉพาะเหตุการณ์ที่ **เสี่ยงต่อการทุจริต** เท่านั้น (ยกเลิกออเดอร์,
void รายการหลังครัวทำแล้ว, แก้ส่วนลด ฯลฯ) — การเปิดออเดอร์ใหม่, เพิ่ม/แก้ไข/ลบรายการระหว่างที่
ออเดอร์ยัง pending, ย้ายโต๊ะ, และรวมบิล **ไม่ถูกบันทึกเลย** ทำให้ผู้จัดการ/ฝ่ายบัญชีที่ต้องการ
ตรวจสอบย้อนหลังว่า "ใครกดสั่งออเดอร์นี้" หรือ "ใครแก้ไขอะไรไปบ้าง" ทำไม่ได้ครบ

## ทำไมสำคัญ

การ audit ทางการเงิน (financial audit) และการบริหารร้าน (restaurant manager) ต้องการ
accountability ที่กว้างกว่าแค่ "ป้องกันทุจริต" — ต้องรู้ด้วยว่าพนักงานคนไหนรับผิดชอบออเดอร์ไหน
เพื่อสอบถามเมื่อมีข้อสงสัย (ไม่ใช่แค่เมื่อมีการกระทำที่ดูน่าสงสัยเท่านั้น)

## ขอบเขตที่ทำ

เพิ่ม action type ใหม่ 6 รายการ ในระบบ audit log เดิม (ใช้ table/infrastructure เดียวกับ
ticket 08 ไม่ต้องสร้างใหม่):

| Action | Entity | Log เมื่อไหร่ |
|---|---|---|
| `order.create` | order | ทุกครั้งที่เปิดออเดอร์ใหม่ (บันทึกพนักงานเสิร์ฟที่กดสั่งจาก `waiterId`) |
| `order.item.add` | order | ทุกครั้งที่เพิ่มรายการเข้าออเดอร์ |
| `order.item.edit` | order_item | เฉพาะตอนแก้ **จำนวน** เปลี่ยนจริง (แก้แค่โน้ตไม่ log) |
| `order.item.remove` | order | ทุกครั้งที่ลบรายการ (entityType เป็น `order` ไม่ใช่ `order_item`
  เพราะ item ถูกลบออกจาก DB จริง ลิงก์ไปหา entityId เดิมไม่ได้อีกแล้ว) |
| `order.move_table` | order | ทุกครั้งที่ย้ายโต๊ะ |
| `order.merge` | order | ทุกครั้งที่รวมบิล (log ผูกกับออเดอร์ปลายทาง) |

## ขอบเขตที่ตั้งใจไม่ทำ

- **แก้โน้ตอย่างเดียวไม่ log** — โน้ต (เช่น "ไม่เผ็ด") ไม่กระทบยอดเงิน/บัญชี ถือว่าไม่ใช่ข้อมูลที่
  financial/manager audit ต้องการเห็น ต่างจาก quantity ที่กระทบยอดขายตรงๆ
- **ไม่ log ทุก field ที่เปลี่ยน แบบละเอียดระดับ diff** — เก็บแค่ summary + metadata สำคัญ (ชื่อ
  เมนู/จำนวนเก่า-ใหม่) พอสำหรับตรวจสอบ ไม่ใช่ full audit ระดับ field-by-field เพราะ noise สูงเกินไป
  สำหรับ POS ร้านอาหารที่มีรายการเปลี่ยนบ่อยมาก

## Acceptance Criteria

- [x] เปิดออเดอร์ใหม่ถูกบันทึกพร้อมชื่อพนักงานเสิร์ฟที่กดสั่ง จำนวนรายการเริ่มต้น
- [x] เพิ่มรายการเข้าออเดอร์ถูกบันทึกพร้อมรายชื่อ/จำนวนที่เพิ่ม
- [x] แก้ไขจำนวนรายการถูกบันทึก (จำนวนเก่า → ใหม่) แต่แก้โน้ตอย่างเดียวไม่ log
- [x] ลบรายการถูกบันทึกพร้อมชื่อ/จำนวนรายการที่ลบ
- [x] ย้ายโต๊ะถูกบันทึกพร้อมโต๊ะต้นทาง/ปลายทาง
- [x] รวมบิลถูกบันทึกพร้อมเลขที่บิลต้นทาง/ปลายทาง
- [x] ทำงานเหมือนกันทั้ง backend จริงและ Demo Mode (mirror ใน `demo_store_orders.dart`)
- [x] มี test คุมครบทั้ง 6 action (`backend/tests/audit-logs.test.js`)

## ดูเพิ่มเติม

ทิกเก็ตนี้ตอบโจทย์ audit มุมผู้จัดการร้าน ("ใครสั่ง/แก้ไขออเดอร์") เท่านั้น — ยังไม่ครอบคลุม audit
ระดับบัญชี/การเงินที่ต้องมองจากฝั่งข้อมูลหลักที่กระทบรายได้ (ราคาเมนู, โปรโมชัน, ต้นทุนวัตถุดิบ)
ดู `docs/tickets/14-financial-audit-trail.md` สำหรับ gap ที่เหลือ
